# Обработка записи

При проблемах связи прочитай `references/reliability.md`, для проверки голосов — `references/diarization.md`. Сначала прочитай `references/workflow.md` для содержания результата. PDF собирай только через `templates/md2pdf.sh` этого навыка.

## Управляемые исполнители BB

Код и вспомогательные скрипты доставляются host-пакетом BB, а не через git pull рабочих машин. В `services` проверяй `runtimeVersion`, `environmentManaged` и `setupStatus`; `submit` сам фиксирует версию для задачи. Каталоги runtime не редактируй и не используй как Git checkout.

При `setupStatus: pending/installing` дождись подготовки окружения; задача может оставаться queued. Ошибку установки смотри по `setupTerminalId`, не ставь пакеты в глобальный Python. Для скачивания используй Python из `services.python` на том же исполнителе и скрипт `<runtimePath>/skills/video-downloader/scripts/download_video.py`. PDF-шаблоны доступны в `<runtimePath>/templates/`; исходный Git checkout для обработки не нужен.

## Сервис и политика вызова

1. Вызови `local_transcribe_services`. Он возвращает машины с готовностью, устройством `mps/cuda/cpu`, зависимостями и занятостью. Mac — основной по умолчанию. `self` означает машину текущего треда. Не объявляй сервис готовым только по статусу connected.
2. Если исходник — ссылка, используй навык video-downloader, который поставляется с плагином; скачивай аудио на выбранного исполнителя либо на машину исходного треда. Пути и machine ID бери из проекта/source, не переноси cwd между машинами.
3. Вызови `local_transcribe_submit`, указав абсолютные `inputPath`, `outputPath`, и при необходимости `inputHostId`, `outputHostId`. В native tool машина текущего треда определяется автоматически. Для RPC укажи `threadId`, если нужен `self`.
4. Политика задаётся в каждом вызове: `service: "mac"`, `fallback: ["self", "<другой-host-id>"]`. По умолчанию запасные — self, затем available (остальные готовые сервисы); не передавай `fallback: []`, если пользователь сам не ограничил выполнение одним сервисом; `fallback: []` запрещает переход. `auto` выбирает готовый сервис, предпочитая MPS, затем CUDA, затем CPU. Движок по умолчанию GigaAM, `speakers: true`. Whisper выбирается явно (`engine: "whisper", speakers: false`). Облачные ASR не добавляются автоматически.
5. Получи `jobId` и `wait`. По умолчанию сервис сам один раз уведомит исходный тред о завершении или ошибке. Сохрани ID в ответе, сообщи, что обработка идёт, и **заверши ход**. Не опрашивай статус/терминал в цикле, не жди через sleep и не создавай отдельного агента-наблюдателя. По вопросу пользователя «как там?» вызови `local_transcribe_status` **один раз** и ответь. По уведомлению проверь статус один раз и продолжи исходное поручение. `notify: false` отключает уведомление для внешнего клиента; RPC должен указать `threadId`, чтобы вернуть результат в тред. Статус остаётся доступен всегда. Для отмены используй `local_transcribe_cancel`; отменённая задача не переходит на запасного. При подтверждённой ошибке или недоступности сервис автоматически выбирает следующий готовый из политики вызова. Потеря связи с уже запущенным терминалом не разрешает повторную обработку на другой машине. Не создавай второй job из-за timeout ожидания. Для нестабильных исполнителей действует lease: короткие разрывы пережидаются, после истечения lease попытка останавливается и сервер переходит к следующему готовому сервису. Возобновившаяся старая попытка результата уже не публикует.
6. `completed` содержит проверенный файл на запрошенной машине. `failed` содержит причины попыток. `returning` с deliveryError означает повтор доставки готовых файлов (до 10 минут); не запускай ASR заново. `return_failed` содержит пути на исполнителе и доставленные артефакты: вызови `local_transcribe_retry_delivery` либо перенеси файлы через `local_transcribe_copy`, не повторяя распознавание. При `interrupted` проверь терминалы и частичные файлы перед новым вызовом.

```json
{"inputHostId":"<id>","inputPath":"/path/recording.webm","outputPath":"/project/transcript.txt","service":"mac","fallback":["self"],"speakers":true}
```

## Ожидание без расхода токенов

Очередь, проверка исполнителя и доставка работают в коде сервиса без LLM. При перезапуске BB незавершённые задачи и уведомления восстанавливаются из хранилища. Уведомление занятому треду становится в очередь BB; повторные тики его не дублируют. Для отменённых задач и архивированных тредов агент не запускается. Старые задачи до включения уведомлений не вызывают массовых пробуждений. Ошибка доставки уведомления видна в `completionNotification`; уведомление повторяется с проверкой очереди/истории. При обработке уведомления не ограничивайся «принято»: выдай запрошенные результаты.

## Состав результата

Сервис распознаёт и подготавливает технические файлы; содержание итогов и подбор результатов определяет агент исходного треда по просьбе пользователя.

- `outputPath` — путь текста; без дополнительных полей возвращается только транскрипт.
- `outputs.segments` — JSON диаризации (исходные речевые интервалы, реплики, длительность и текст).
- `outputs.audio` — извлечённое аудио AAC/M4A.
- `outputs.source` — побайтовая копия исходной записи.
- `outputs.samples` — ZIP с короткими анонимными примерами кластеров для проверки голосов.
- `speakerCount` — известное число говорящих, только из подтверждённых сведений пользователя/встречи; не из размера всего справочника команды. Пять кластеров при ограничении 5 ещё не доказывают пять корректно разделённых людей.
- Все пути абсолютные, разные и относятся к `outputHostId`. Существующие файлы не заменяются.
- «Текст и аудио» означает запросить `outputs.audio`; «сохрани всё» — все три дополнительных файла. «Сделай итоги» добавляет последующую работу агента; ASR-сервис сам итоги не сочиняет. Если состав не указан, выдавай транскрипт либо транскрипт + запрошенные итоги; оригинал сохраняется независимо.
- По возможности держи исходник на устойчивой машине текущего проекта, чтобы сон Mac не сделал файл недоступным запасному исполнителю. Ссылку сначала скачай через video-downloader (yt-dlp), затем передай её локальный путь сервису. Видео/аудио принимает ffmpeg; не обещай обработку неподдерживаемого формата, закрытой ссылки без доступа или DRM.

## Люди, задачи и итоги

Если нужны имена участников и назначения задач, прочитай `references/project-people.md`. Сервис сохраняет техническую диаризацию, а агент проекта составляет `speaker-map.json` и задачи с основаниями. Номера Speaker N не постоянны между записями. Не присваивай людям задачи по неподтверждённым догадкам об имени.

## Итоги и PDF

- Если запрошена только расшифровка, выдай транскрипт. Для итогов/саммари подготовь Markdown и PDF по `references/workflow.md`. Используй контекст исходного треда для названия, участников, решений и задач; не выдумывай имена и сроки.
- Длинный транскрипт читай через context-mode, если доступен.
- PDF: `bash <skill>/templates/md2pdf.sh <итоги.md> [<итоги.pdf>]`. Можно собрать на машине исходного треда или на Mac с готовыми зависимостями, передав Markdown и результат через `local_transcribe_copy`.
- При ошибке PDF сообщи её и выдай готовый Markdown. Проверь созданный PDF. Дай ссылки на все результаты.
- Сохраняй оригиналы. Не удаляй рабочие файлы автоматически и не коммить записи, модели или транскрипты.

## Ограничения

Плагин предоставляет очередь задач и API оркестрации через host RPC и терминалы BB. Он не заменяет микрофон BB. Итоги пишет агент исходного треда; локальная ASR-модель на Mac делает распознавание. Модели готовятся установщиком scripts/setup_worker.py --download-model. Обработка читает локальный кэш ModelScope без проверки доступа к хабу.
