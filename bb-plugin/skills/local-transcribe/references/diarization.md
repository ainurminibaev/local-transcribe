# Диаризация, участники и проверка качества

Диаризация группирует речевые интервалы по сходству голосов. Кластер Speaker N не равен подтверждённому человеку. Автоматическая оценка может объединять участников, особенно на длинной записи с похожими голосами или короткими репликами. Номер спикера не переносится между встречами.

Если число говорящих известно, передайте `speakerCount`, например 5. Используется кластеризация нормализованных embeddings с ограничением числа кластеров; она не строит плотную N×N spectral-матрицу для длинной записи. Это ограничение помогает разделению, но само по себе не доказывает, что каждый кластер соответствует одному человеку.

Для проверки запросите `outputs.segments` и `outputs.samples`. JSON содержит исходные речевые интервалы, реплики, длительность, число полученных кластеров, заданное ограничение и предупреждения. ZIP содержит до трёх коротких анонимных примеров каждого кластера и `index.json` с таймкодами. По примерам можно проверить редкий голос и дать человеку имя, не меняя технический распознаватель.

В рабочей папке исполнителя сохраняются `speaker-features.npz` и `asr-tokens.json`. Они привязаны к SHA-256 декодированного аудио, а ASR-кэш также к конфигурации движка. Повторная диаризация той же записи может менять число кластеров и пересобирать текст без повторного извлечения embeddings или ASR:

```sh
python3 diarize_ms.py <тот-же-вход> --speaker-count 5 --cache-dir <предыдущая-work-папка> --out <новый-транскрипт.txt> --json-out <новая-диаризация.json>
```

Первая обработка до внедрения кэша требует одного повторного прогона. Исходный результат следует сохранять отдельно. Кэши и голосовые примеры не включаются в Git и не копируются в bb-config.

Сопоставление людей и задач выполняет агент проекта по `references/project-people.md` навыка. Для смешанного кластера нужна привязка отдельных реплик/интервалов (`turnOverrides`), а не одно имя на весь Speaker N. Неподтверждённое имя или срок явно помечается; само число кластеров не подтверждает число участников.

## Эксперимент FluidAudio

Инструкция сборки и сравнения находится в `tools/fluidaudio-diarizer/README.md` репозитория.
Для 3–5 записей сравниваем время и DER по ручной разметке, включая
перекрытия и короткие реплики. До проверки основной путь — ModelScope.

## Автоматические подсказки GigaAM

Проект задания определяется по окружению исходного треда. Словарь собирается
из названия этого проекта, его AGENTS.md, глоссариев, недавних расшифровок и итогов
в его checkout. Зарегистрированные вложенные проекты и символические ссылки
пропускаются. Если проект неизвестен, окружение сменило проект или запись лежит
в checkout другого проекта, применяется только общий словарь, если он настроен.

Общий слой `neutralVocabulary` по умолчанию пуст; в него можно явно добавить
нейтральные для всех проектов термины, например имя владельца или общие бренды.
Проектные названия и автоматически извлечённые термины в общий слой не попадают.
Отдельные адресные книги автоматически не читаются. Общий и проектный словари
вместе ограничены 64 терминами. Исполнитель получает их в файле попытки;
тексты источников и термины не попадают в статус или уведомление BB.


Приоритет у явных имён и терминов в глоссарии, затем у имён и названий
из проектных документов и итогов. Термин, найденный только в черновых
расшифровках, должен повторяться хотя бы в двух независимых встречах.
Версии расшифровки одной встречи не дают дополнительных голосов.
Сборщик ограничивает глубину обхода, число документов и объём чтения;
пропускает адресные книги, кодовые блоки, служебные слова и токены,
в которых перемешаны кириллица и латиница. Есть отдельные места для
продуктов и сервисов и для регулярных падежных форм явно указанных имён.

Установленный GigaAM GGUF/transcribe.cpp 0.4.1 не принимает словарь.
Для проверки контекстного CTC на отдельном исполнителе можно задать
`LOCAL_TRANSCRIBE_GIGAAM_ONNX_DIR` с совместимыми файлами
`model.int8.onnx` и `tokens.txt` GigaAM v3 E2E CTC. Это выбирает ONNX
для этого процесса; модель загружается отдельно. Статус исполнителя
сообщает `contextVocabulary`. Декодер даёт приоритет только целому термину
среди близких по акустической вероятности вариантов. Термины с символами
вне словаря модели пропускаются. Смену формата по умолчанию нужно проверять
отдельно на именах, брендах и обычной речи.
