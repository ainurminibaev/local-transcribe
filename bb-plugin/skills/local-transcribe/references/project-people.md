# Люди и задачи в контексте проекта

Распознаватель возвращает анонимные голоса и текст. Сопоставление людей, решений и задач выполняет агент исходного проекта, используя контекст этого проекта и конкретной встречи.

1. Прочитай инструкции проекта и существующие справочники команды/контактов. При необходимости веди `.bb/local-transcribe/people.json`: `version: 1`, массив `people` с `id`, `name`, `aliases`, `role`. Добавляй людей только из предоставленного или подтверждённого контекста. Этот справочник не содержит записей голоса, эмбеддингов и секретов; автоматически не коммить его.
2. Для каждой встречи составь рядом с результатами `speaker-map.json`: SHA-256 записи, `speakers` с `speaker` (номер из этой записи), `personId` или null, `status` (`confirmed`, `inferred`, `unknown`, `mixed`), `evidence` (короткий фрагмент и таймкод/ссылка на контекст). Самопредставление и явное подтверждение пользователя — сильные основания; обращение к собеседнику или знание его роли само по себе не доказывает, кто говорит.
3. Если один кластер содержит несколько людей, отметь его `mixed`; используй `turnOverrides` с `start`, `end`, `personId`, `status`, `evidence` для отдельных реплик. Не закрепляй одного человека за всем смешанным кластером.
4. Номера Speaker N локальны для записи. Не переносить «Speaker 0 = Айнур» на следующую встречу. Не выдавать диаризацию за распознавание личности по голосу: система без обучения на голосах этого не делает.
5. При неуверенности используй «Speaker N (предположительно …)» или оставь имя неизвестным. Можно задать один компактный вопрос по нескольким людям после подготовки черновика, сохранив полезную работу. Не запускать повторно ASR ради догадки об имени.
6. Извлекай только зафиксированные задачи отдельно от предложений. В таблице `Кто | Что | Срок` и в `tasks.json` храни описание, `assigneePersonId` или null, уверенность/основание, срок или null и таймкод доказательства. Назначение задачи человеку может следовать из прямого упоминания его имени, даже если личность говорящего неизвестна. Не назначай исполнителя по одной лишь роли или номеру спикера.
7. Неподтверждённые назначения и сроки явно помечай. Предложения агента вынеси отдельно. Если пользователь просит создать задачи в существующем трекере проекта и дал доступ, используй интеграцию этого трекера; при обычном запросе итогов подготовь список задач, не создавая внешние поручения и не отправляя сообщения участникам.
8. Итоги Markdown/PDF должны ссылаться на исходник, транскрипт и карту спикеров при её наличии. В кратком ответе отметь, какие имена подтверждены, а какие остаются предположениями.

Пример карты (идентификаторы людей берутся из проекта):

```json
{"version":1,"recordingSha256":"...","speakers":[{"speaker":0,"personId":null,"status":"unknown","evidence":[]}]}
```

Для обработки без списка участников можно закончить транскрипт и подготовить нейтральные итоги с анонимными спикерами. Имена и задачи уточняются без повторной обработки аудио.
