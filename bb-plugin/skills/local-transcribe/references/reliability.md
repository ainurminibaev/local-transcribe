# Выбор исполнителя и нестабильная связь

Политика по умолчанию: Mac → self (машина вызывающего треда) → available (остальные готовые сервисы). Каждый исполнитель пробуется один раз. Вызов может передать упорядоченный `fallback`; `[]` следует задавать только по явной просьбе пользователя работать на одной машине.

- До запуска недоступный или неготовый сервис пропускается. Для устойчивого перехода храните исходник на машине исходного проекта: если единственная копия записи находится на спящем Mac, другой сервер не сможет прочитать отсутствующий файл.
- Во время распознавания сервер продлевает lease каждые 15 секунд. Короткие разрывы связи пережидаются. После истечения lease (120 секунд по умолчанию) и 10 секунд запаса выбирается следующий сервис.
- Исполнитель проверяет lease по настенным часам, которые учитывают сон ноутбука, и завершает процесс распознавания с дочерними процессами при его истечении. Проснувшаяся старая попытка больше не продлевается. Сервер принимает результат только текущей попытки: старый локальный результат не подменяет новый.
- После успешного распознавания доставка отделена от вычислений. Временные ошибки повторяются до 10 минут; уже доставленные файлы проверяются по размеру и SHA-256. Повтор доставки не запускает распознавание заново. Другое существующее содержимое не заменяется.
- `return_failed` сохраняет пути на исполнителе и список доставленных артефактов. `local_transcribe_retry_delivery` / RPC `retryDelivery` повторяет только доставку после восстановления связи.
- Отмена переводит задачу в `cancelled`, прекращает продление lease и пытается закрыть терминал. Запасной исполнитель после отмены не запускается.

Настройка lease: `bb plugin config local-transcribe set leaseSeconds 120` (от 30 до 240). Доступность сервиса, progress stage, ошибки соединения и срок lease видны в `local_transcribe_status`.

Перезапуск/обновление плагина во время большой передачи может прервать host RPC текущего поколения. Исходник сохраняется; обновления лучше выполнять между задачами. Работающий процесс в терминале не перезапускается из-за обновления. Подготовка, состояние которой потеряно при обновлении, помечается `interrupted`, чтобы не создать скрытый дубликат.
