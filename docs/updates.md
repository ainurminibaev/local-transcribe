# Штатные обновления BB

Плагин устанавливается на сервере BB один раз из Git-релизов:

```sh
bb plugin install 'git:https://github.com/ainurminibaev/local-transcribe.git@semver:^0.2.0' --yes
```

BB проверяет совместимые Git/npm-релизы примерно раз в 6 часов. Новая версия появляется в штатных обновлениях; применение запускается в интерфейсе или `bb plugin update local-transcribe`. Проверку можно выполнить сразу: `bb plugin outdated`. Фоновая проверка сама не устанавливает обновления.

После одного обновления на сервере BB host-пакет при следующем обращении доставляет Python-код на зарегистрированные машины. Машина офлайн получит его, когда подключится и к ней обратятся. Версии лежат отдельно в постоянных данных плагина, а задачи сохраняют точный путь и версию использованного движка. Уже запущенные процессы не зависят от удаления старого Git-кэша BB. Код рабочих checkout не нужен для исполнения.

Окружения Python подготавливаются в данных плагина и повторно используются, пока зависимости не изменились. На Mac можно принять уже работающие системные библиотеки в отдельное venv, не изменяя глобальные пакеты. На Linux используются CPU-версии PyTorch. Обновлённые зависимости ставятся в другое окружение; старое не меняется под работающей задачей. Веса остаются в локальном кэше.

Исполнителей задаёт `workerHosts` (JSON-массив machine ID); источники проекта также служат регистрацией для совместимости. На незарегистрированные машины тяжёлые зависимости не устанавливаются, но их агенты могут обращаться к общему API. `autoSetup` управляет подготовкой окружений. Статусы `runtimeVersion`, `runtimeSha256`, `environmentManaged`, `setupStatus` видны в `services`.

Первичная подготовка/повтор после устранения ошибки: RPC `prepareWorkers` с `{}` или `{"force":true}`. Установочные процессы видны в обычных терминалах BB. ffmpeg и Python должны быть установлены на машине заранее; плагин не запускает системный пакетный менеджер.

## Выпуск версии

1. Изменить версию в `bb-plugin/package.json` и npm lock-файле.
2. Выполнить `python3 scripts/sync_runtime.py`, `python3 scripts/sync_release.py` и проверки.
3. Собрать и проверить плагин, сделать commit/push.
4. Создать новый неизменяемый тег `vX.Y.Z`, отправить его в Git. Старые теги не передвигать.
5. Проверить `bb plugin outdated`, затем применить обновление через BB и проверить версии/пробное распознавание на исполнителях.

Текущее ограничение `^0.2.0` допускает совместимые исправления 0.2.x. Переход на другую minor-ветку до 1.0 требует явного выбора диапазона.
