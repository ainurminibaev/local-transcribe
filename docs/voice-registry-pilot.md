# Пилот подтверждения голоса

Пилот работает поверх готового транскрипта GigaAM с диаризацией. Он связывает номера спикеров с именами только после ответа пользователя. Автоподписей в этой версии нет. Порог внутри проекта 0,80 с отрывом от второго кандидата 0,08. Для межпроектной подсказки нужны 0,85 и отрыв 0,10. Для обоих уверенных совпадений нужны два чистых отрывка, указавших на одного кандидата. Эти значения используются только для порядка подсказок. Они не калиброваны для автоматической идентификации.

## Активация после утверждения выпуска

Пилот выключен, пока список `voicePilotProjects` пуст. В настройках плагина задайте JSON-массив идентификаторов приватных проектов одного доверенного владельца BB. Пилот не предназначен для проекта, в котором разные люди имеют разные права на голосовые профили. Затем задайте `voiceRegistryKey` в секретном поле BB. Оно принимает 64 шестнадцатеричных символа, например результат `openssl rand -hex 32`, созданный локально. Ключ нужно хранить вне Git, переписки и снимков BB. Смена ключа без прежнего значения делает записи недоступными. Храните резерв ключа только если сознательно резервируете сам реестр.

Ключ и реестр не входят в экспорт переноса плагина или снимок настроек. Реестр хранится в SQLite плагина: имена, привязки и векторы шифруются AES-256-GCM. Полное резервное копирование диска или данных BB нужно настраивать отдельно. Удаление профиля применяется к работающему реестру. Уже выданные именные файлы и внешние резервные копии регулируются отдельно.

## Как пользоваться

1. Получите расшифровку со спикерами в исходном треде. Поддерживаются новые задания из проекта пилота с подготовленным исполнителем: исходная запись и интервалы должны ещё быть доступны. У старых задач может не быть сведений о проекте или скрипта подготовки отрывков.
2. По запросу пользователя вызовите `local_transcribe_voice_map` для ID задания. Карта покажет подтверждённые имена и номера с доступными отрывками. Вызывайте `local_transcribe_voice_review` по одному номеру. В форме «Говорящий N — кто?» воспроизводятся ровно пять секунд. Если подходящего отрывка нет, оставьте номер без имени. В форме можно пропустить вопрос.
3. Введите имя для этой встречи или выберите существующий профиль. Сохранение отпечатка и поиск в других проектах нужно отдельно отметить в форме. Отпечаток сохраняется только при подтверждённом согласии участника и только для прослушиваемого отрывка. При первом совпадении с человеком из другого проекта форма просит подтвердить, что это тот же человек, и явно разрешить добавить профиль в текущий проект.
4. «Говорящий N — это Анна, исправь» открывает ту же форму с предложенным именем. Исправление обновляет карту встречи. Если старая подпись зарегистрировала образец в неверном профиле, её образец убирается. Новый образец требует отдельного согласия.
5. Для готового файла с именами вызовите `local_transcribe_voice_render`. Это отдельная копия с подтверждёнными именами рядом с оригиналом. Номера с неопределённым голосом и пометки «говорящий неясен» сохраняются. Исходник не перезаписывается.
6. «Удали голосовой профиль Анны» сначала находит ID с `local_transcribe_voice_profiles`, затем вызывает `local_transcribe_voice_forget`. Пользователь подтверждает удаление в форме. Удаляются векторы и активные привязки во всех проектах. Выданные ранее файлы можно исправить отдельно по запросу.

Форма доступна только в исходном треде задания. Ссылка на отрывок действует до закрытия формы или 10 минут. Звук выдаётся напрямую из исходной записи и не сохраняется в реестре. Исполнитель не получает имена из реестра. При его недоступности сохраняются исходный транскрипт и уже подтверждённая карта.

Движок диаризации может быть ModelScope или FluidAudio, так как пилот читает общую схему интервалов. Для обоих используется уже установленный CAM++ с одинаковым входом PCM 16 кГц. Векторы другой версии весов не сравниваются. FluidAudio отдельно ещё предстоит проверить на Mac.
