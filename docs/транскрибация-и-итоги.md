# Инструкция: транскрибация и итоги (полный пайп)

Единый процесс для **любого** аудио/видео в проекте — встречи, разборы, локальные файлы, YouTube/ссылки (после скачивания). Транскрипт **ВСЕГДА со спикерами** (жёсткое требование пользователя).

Краткие правила и команды-триггеры — в `CLAUDE.md`. Здесь — подробная процедура.

---

## Шаг 1. Извлечь аудио (если исходник — видео)

Видео нам не нужно — нужен звук. Из любого видео извлекаем аудио и кладём рядом. **Оригинал-видео НЕ удаляем здесь** — это делает отдельная чистка (`ИНСТРУКЦИЯ — уборка.md`).

```bash
export DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib
ffmpeg -nostdin -y -i "in.webm" -vn -c:a aac -b:a 96k "in.m4a" -hide_banner -loglevel error
```

## Шаг 2. Транскрибация со спикерами

Единый инструмент в отдельном git-репозитории: **`~/local-transcribe/`** (GitHub `github.com/ainurminibaev/local-transcribe`, приватный).

```bash
python3 ~/local-transcribe/diarize_ms.py "<файл>" --out "<папка>/transcript.txt"
```
Результат: строки `Speaker N [mm:ss]: текст`. Можно подавать прямо `.m4a`. Долгие записи запускать в фоне.

**Состав пайплайна:**
- **Текст:** GigaAM v3 (из Handy), CTC, препроцессинг точь-в-точь как в крейте `transcribe-rs`. Fallback по тексту: GigaAM → Whisper medium (whisper.cpp) → Rev.ai (MCP `mcp__revai__submit_and_wait`, тоже даёт спикеров).
- **Спикеры (диаризация):** ModelScope 3D-Speaker (VAD FSMN + CAM++ эмбеддинги + кластеризация), PyTorch на MPS (GPU Mac). **Токен HuggingFace НЕ нужен.**
- `transcribe.py` (в том же репо) — вариант БЕЗ спикеров (~70 с). Только если разметка спикеров явно не нужна.

**Важно:**
- **Handy не трогаем** — только читаем её модели в `~/Library/Application Support/com.pais.handy/models/`.
- **Память:** всё одноразовым процессом (загрузил → отработал → вышел). Никаких демонов. После прогона при сомнениях: `pgrep -fl "diarize|transcribe|whisper-server"`.
- **Время:** ~8–10 мин на 40-мин запись (с диаризацией). Первый запуск дольше — разово качаются модели ModelScope в `~/.cache/modelscope`.
- **Зависимости (один раз):** brew: `whisper-cpp ffmpeg pango`; pip: `onnxruntime librosa soundfile numpy torch torchaudio modelscope funasr umap-learn hdbscan addict datasets weasyprint`.

## Шаг 3. Нормализация терминов

ASR искажает названия (бренды, модели, имена). Нормализовать по смыслу. Для проектных встреч сверяться с глоссарием проекта, если он есть.

## Шаг 4. Итоги — только если просили «сделай итог/итоги»

Если просили только «расшифруй/транскрибируй» — остановиться на `transcript.txt` и **спросить, нужны ли итоги**. Для итогов — собрать два файла: исходник `.md` и `.pdf` из него (для разборов — `инструкция.md`).

**Имя файла итогов для встреч** (внутри подпапки `Итоги встреч/…`): `<Название встречи> (<проект>), ДД.ММ — итоги.md` / `…— итоги.pdf`. Пример: `Синк по проекту, 25.06 — итоги.pdf`. Название и дату берём из имени подпапки, проект — из контекста. Для разборов видео имя главного файла — `итоги.md`/`инструкция.md` (папка уже названа по сути видео).

### Структура итогов (строго этот порядок)

1. **Заголовок** — название, дата, длительность, участники.
2. **Короткий лид** (1 абзац) — о чём встреча.
3. **📝 Подробно** — основная длинная часть: разделы по темам, в конце «Открытые вопросы».
4. **⚡ Кратко (TL;DR)** — сжатые тезисы.
5. **Зафиксированные решения** — список.
6. **Зафиксированные задачи** — таблица `Кто | Что | Срок`.
7. **Файлы** — ссылки на `recording.*`/аудио, `transcript.txt`.

То есть: **сначала длинно, в конце — кратко + решения + задачи**.

### Markdown-разметка: обязательные правила (иначе ломается вёрстка PDF)

- **Перед любым списком — пустая строка.** Если список (`- `, `* `, `1. `) идёт сразу под строкой-абзацем без пустой строки, pandoc приклеивает пункты к абзацу и они НЕ переносятся. Неправильно: `**Участники:**` ↵ `- Иван`. Правильно: `**Участники:**` ↵ ↵ `- Иван`. После заголовка (`#…`) пустая строка не обязательна.
- После списка перед следующим абзацем — тоже пустая строка.
- **Проверка перед сборкой PDF** (должна давать пустой вывод):
  ```bash
  awk 'NR>1 && $0 ~ /^[-*+] |^[0-9]+\. / && prev !~ /^[-*+] |^[0-9]+\. |^[[:space:]]*$|^#/ {print NR": "$0} {prev=$0}' "итоги.md"
  ```

### Сборка PDF

CSS-шаблон — `.templates/итоги.css`. Скопировать рядом как `.style.css` и собрать:

```bash
cp ".templates/итоги.css" "<папка>/.style.css"
cd "<папка>"
export DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib   # фикс pango/dyld для weasyprint
pandoc "итоги.md" -o "итоги.pdf" -s --pdf-engine=weasyprint -c ".style.css" -M lang=ru
rm -f .style.css
```

Предупреждения weasyprint про неизвестные CSS-свойства (`overflow-x` и т.п.) можно игнорировать — PDF собирается. Кириллица рендерится корректно (`-M lang=ru` + системный шрифт из шаблона).
