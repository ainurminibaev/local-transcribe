# Правило выполнения в BB

По умолчанию основной исполнитель — Mac с GPU. Тред задаёт политику вызова: `service: "mac"`, `fallback: ["self", "<host-id>"]`. API возвращает список готовых сервисов; переход на запасной происходит автоматически только в рамках переданного списка после подтверждённой недоступности или ошибки. При короткой потере связи ждать проверки состояния. По истечении lease прежняя попытка прекращается, после чего выбирается запасной; устаревший результат не принимается. По умолчанию запасные — машина исходного треда, затем остальные готовые сервисы (`["self", "available"]`); `fallback: []` отключает переходы. Движок меняется только явно через параметр `engine`; облачный ASR не выбирается автоматически.

Код, инструкции, скачивание видео и PDF-шаблоны хранятся в одном репозитории `local-transcribe`. Точный путь и машину искать в `bb project list --json`, а не подставлять путь текущего треда. Git-операции выполняются в checkout на Tru; Mac хранит рабочую копию для вычислений.

# Инструкция: транскрибация и итоги (полный пайп)

Единый процесс для **любого** аудио/видео в проекте — встречи, разборы, локальные файлы, YouTube/ссылки (после скачивания). Транскрипт **ВСЕГДА со спикерами** (жёсткое требование пользователя).

Краткие правила и команды-триггеры — в `CLAUDE.md`. Здесь — подробная процедура.

---

## Шаг 1. Извлечь аудио (если исходник — видео)

Видео нам не нужно — нужен звук. Из любого видео извлекаем аудио и кладём рядом. **Оригинал-видео НЕ удаляем здесь** — это делает отдельная чистка (`ИНСТРУКЦИЯ — уборка.md`).

```bash
export DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib
ffmpeg -nostdin -y -i "in.webm" -vn -c:a aac -b:a 96k "in.m4a" -hide_banner -loglevel error
```

## Шаг 2. Транскрибация со спикерами

Перед запуском встречи уточни, сколько человек говорит на записи и как их зовут, если этих сведений ещё нет в запросе или исходном треде. Спроси только недостающее. Когда число подтверждено, укажи его в `speakerCount` для BB или `--speaker-count N` для скрипта. Имена привязывай к голосам после проверки соответствия.

Единый инструмент в отдельном git-репозитории: **`~/local-transcribe/`** (GitHub `github.com/ainurminibaev/local-transcribe`, приватный).

```bash
python3 ~/local-transcribe/diarize_ms.py "<файл>" --out "<папка>/transcript.txt"
```
Транскрипт содержит строки `Speaker N [mm:ss]: текст`. Если слово пересекает границу двух голосов или говорящий не определяется, строка начинается с `Говорящий неясен`. Диапазоны без распознанного текста отмечаются отдельно. Можно подавать прямо `.m4a`. Долгие записи запускать в фоне.

**Состав пайплайна:**
- **Текст:** GigaAM v3 (из Handy), CTC, препроцессинг точь-в-точь как в крейте `transcribe-rs`. Альтернативы по тексту (без автоматического переключения): GigaAM; Whisper или Rev.ai доступны только после явного выбора пользователя.
- **Спикеры (диаризация):** ModelScope 3D-Speaker (VAD FSMN + CAM++ эмбеддинги + кластеризация), PyTorch на MPS (GPU Mac). **Токен HuggingFace НЕ нужен.**
- `transcribe.py` (в том же репо) — вариант БЕЗ спикеров (~70 с). Только если разметка спикеров явно не нужна.

**Важно:**
- **Handy не трогаем** — только читаем её модели в `~/Library/Application Support/com.pais.handy/models/`.
- **Память:** всё одноразовым процессом (загрузил → отработал → вышел). Никаких демонов распознавания. После прогона при сомнениях: `pgrep -fl "diarize|transcribe|whisper-server"`.
- **Время:** ~8–10 мин на 40-мин запись (с диаризацией). Модели заранее готовит установщик в `~/.cache/modelscope`; само распознавание читает локальные файлы.
- **Зависимости (один раз):** brew: `whisper-cpp ffmpeg pango`; pip: `onnxruntime librosa soundfile numpy torch torchaudio modelscope funasr umap-learn hdbscan addict datasets weasyprint`.

## Шаг 3. Нормализация терминов

ASR искажает названия (бренды, модели, имена). Нормализовать по смыслу. Для проектных встреч сверяться с глоссарием проекта, если он есть.

## Шаг 4. Итоги — только если просили «сделай итог/итоги»

Если просили только «расшифруй/транскрибируй» — остановиться на `transcript.txt` и **спросить, нужны ли итоги**. Для итогов — собрать два файла: исходник `.md` и `.pdf` из него (для разборов — `инструкция.md`).

**Имя файла итогов для встреч** (внутри подпапки `Итоги встреч/…`): `<Название встречи> (<проект>), ДД.ММ — итоги.md` / `…— итоги.pdf`. Пример: `Синк по проекту, 25.06 — итоги.pdf`. Название и дату берём из имени подпапки, проект — из контекста. Для разборов видео имя главного файла — `итоги.md`/`инструкция.md` (папка уже названа по сути видео).

### Структура итогов (строго этот порядок)

1. **Заголовок** — название, дата, длительность, участники.
2. **Короткий лид** (1 абзац) — о чём встреча.
3. **📝 Подробно** — основная длинная часть: разделы по темам, в конце «Открытые вопросы».
4. **⚡ Кратко (TL;DR)** — сжатые тезисы.
5. **Зафиксированные решения** — только явно принятые решения. Предложения, варианты и разногласия вынеси в «Открытые вопросы».
6. **Зафиксированные задачи** — таблица `Кто | Что | Срок`. Указывай человека и срок только при явном назначении и договорённости. При отсутствии подтверждения пиши «не назначен» или «не согласован».
7. **Пробелы в расшифровке** — укажи диапазоны из `transcriptGaps` или пометок в транскрипте. Различай речь, обнаруженную диаризацией, и интервалы, где речь не подтверждена. По неполной записи помечай выводы, которые нельзя проверить.
8. **Файлы** — ссылки на `recording.*`/аудио, `transcript.txt`.

То есть: **сначала длинно, в конце — кратко + решения + задачи**.

### Markdown-разметка

Правило «пустая строка перед списком» соблюдать при написании, но **гарантирует его сборка**, а не дисциплина: сборщик `md2pdf.sh` прогоняет markdown через `normalize_md.py`, который сам вставляет недостающие пустые строки перед списками (`- `, `* `, `1. `). Поэтому даже если строка-подзаголовок вида `**Участники:**` окажется вплотную к списку — вёрстка не сломается. Ручную awk-проверку держать не нужно.

### Сборка PDF — ТОЛЬКО через обёртку

Единая точка входа — `templates/md2pdf.sh`. Она сама: нормализует markdown, копирует CSS, ставит DYLD-фикс, глушит шумные warning'и, чистит временные файлы.

```bash
"templates/md2pdf.sh" "<папка>/итоги.md"          # PDF рядом, тем же именем
# или явно указать выход:
"templates/md2pdf.sh" "<папка>/итоги.md" "<папка>/итоги.pdf"
```

**Не собирать pandoc вручную** — иначе теряется нормализация и возвращается баг склеенных списков. Предупреждения weasyprint про неизвестные CSS-свойства (`overflow-x` и т.п.) обёртка отфильтровывает; кириллица рендерится корректно (`-M lang=ru` + системный шрифт из шаблона).
